Review date: 2026-10-15. Proposed work, not installed in the personal runtime.

## Scan audit and first change

The former private repository points to this repository as canonical. The catalog has 374 boards: Greenhouse 124, Personio 89, Ashby 57, Lever 42, SmartRecruiters 24, Workable 22 and Recruitee 16. The dated endpoint audit records 160 verified, 99 unverified, 93 not_found and 22 deferred_provider_quota. These are historical endpoint observations, not today's operational results or vacancy availability.

The scheduler excludes embedded audit entries with enabled=false unless RETRY_UNAVAILABLE_BOARDS=true. It rotates primary and Workable pools separately; default total capacity is 80, including at most two Workable boards. With all 22 Workable boards active, their nominal visit cycle alone takes 11 runs. Budget 270 seconds, page limit three and provider cooldowns can extend actual completion. Pagination checkpoints resume later; attempted batches do not prove successful requests. Learned boards also join the pools. Workable appears after primary boards, so repeated budget exhaustion may delay that pool: measure actual progress before changing scheduling.

First change adds report.rotation to JSON and Markdown: active pool sizes, scheduled capacity, next offsets and nominal visit cycles. Zero scheduling capacity yields null rather than a false ETA. No rotation/state/filter/trigger changes. Existing report fields remain compatible. Synthetic regression checks cover independent pools, empty pools, zero capacity and no mutation. The canonical collector and generated matcher copy are synchronized.

Runtime limitation: no fresh private candidates.json, processed_jobs.json or Apps Script execution log was inspected. Do not claim the installed code equals GitHub or that a full cycle completed. Next read-only validation should compare collector_version, board_pages, board_coverage, board_progress, pool cursors and execution duration across at least 11 existing runs. ## Implementation sequence

Implemented locally (not installed): an opt-in adapter reads up to five explicitly registered published Docs/Notion recruiting pages, with a pasted-text fallback for dynamic pages. Results remain unverified discovery leads and use normal queue/dedup/catchup rules. Supported ATS links can teach boards. Public-page web discovery and multi-vacancy extraction remain unimplemented. See [adapter configuration and limits](public-recruiting-sources.md).

Implemented locally (not installed): market discovery accepts DISCOVERY_CATCHUP_DAYS=30 (default) or 60. The report includes discovery_catchup counts and each emitted lead has a catchup date_status. Leads published outside the rolling window are omitted from this report's discovery_leads but retained in discovery_review; changing to 60 can surface them again. Unknown/invalid/future publication dates remain reviewable as unknown. First-seen is preserved on refresh; migrated leads without any reliable observation timestamp keep it unknown. Naive ISO timestamps are interpreted as UTC. This selects from available feed/backlog data, not an exhaustive reconstruction of historical vacancies. Existing Arbeitnow head refresh and resumable sweep remain unchanged. Supported ATS references can now also be learned from eligible retained leads during feed absence, with existing domain checks and no fit endorsement. No new discovery provider or paid service was added.

Follow-up validation: complete page-zero listings already populate the same-run cache. New regression coverage verifies Workable reuse after quota exhaustion, empty listings, board isolation and malformed-response rejection. ProviderQuota now has error_type provider_quota, separate from provider_cooldown; both remain retryable. Scheduling and request limits remain unchanged. Validation of a pending role on a different board can still be deferred after collection consumes both requests; this requires a separate scheduling change, not another cache.

## Shortlist contract: up to 3 strong matches + 2 wildcards

Strong matches require a current complete employer JD, no hard conflict, adequate evidence and the existing positive recommendation gates. Wildcards require plausible transferable evidence and a written reason for the adjacent role plus explicit gaps. They must pass the same language, location, authorization and closure checks; semantic similarity cannot bypass them. Use distinct canonical vacancy identities and favor variety across companies. Never relabel a discovery lead as verified or transfer an assessment between profiles.

If only one strong match and no credible wildcard exist, show 1 + 0 and explain the unfilled slots. Do not manufacture five recommendations. Keep all other eligible roles in the queue; shortlist size is separate from the 20-item review packet cap. Record why a role was selected, evidence citations, unknowns, verification date and source.

## Evaluation and rollout

Primary metrics: relevant opportunities found against a manually labeled sample, relevant opportunities missed, false positive rate, duplicates, source/pool freshness, backlog age, review time and unsupported claims. Interview outcomes are a delayed secondary signal with employer confounding, never the sole optimization target. Establish a baseline before setting improvement targets.

For personal validation, compare old and proposed reports offline with private inputs kept outside Git. Public tests use fictional examples. Publish code only after normal checks; installing Apps Script, replacing live state or deploying requires explicit confirmation. Roll back an installation by restoring the prior script version while preserving the state schema and existing trigger. Do not create another writer, folder or schedule.
