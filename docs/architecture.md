# Architecture

JobOps has one user workspace and two optional entry points: a browsing extension and a scheduled private collector. Both feed the opportunity list; the human owns the decision and application status.

The extension extracts visible job text and uses `core/triage` for preliminary screening. Saving a browser role deliberately does not certify employer verification: the dashboard asks the user to confirm the original employer posting. The shared Chrome-local workspace uses `jobopsWorkspaceV1`; the profile uses the existing `candidateProfileSettings` key, preserving extension profile compatibility. Local HTTP mode uses the same schema in localStorage, on a separate origin.

The collector reads private Drive evidence and Charter plus a read-only Google Tracker. It rotates public ATS boards, persists pending roles/checkpoints/cooldown in Drive state, rechecks employer postings and writes a bounded candidate packet. Discovery leads are kept separate from employer-verified candidates. Workable has a dedicated bounded request budget and a persisted rate-limit cooldown. Personio fallback needs fresh XML presence, exact identity, an application link and an extractable complete description.

`services/collector` is authoritative for Apps Script. The copies in `services/matcher/apps-script` exist for synthetic tests and are generated by `scripts/sync_collector.py`. The evidence schema, prompt and policy are sourced from the Python matcher; its generation script updates canonical `ScoringConfig.gs` and the test copy. No running Google installation is silently changed by a GitHub commit.

Browser triage and private evidence scoring remain distinct: triage uses declared screening signals; evidence scoring requires exact source citations and a deterministic decision gate. The dashboard displays imported evidence assessments as source-specific assessments rather than assuming that they belong to its current profile. Human review is required in both cases.

The workspace has no backend, telemetry, paid scoring call or submission flow. Native backups and CSV export support portability. Demo roles and edits remain in memory and never enter real tracking exports. Collector inputs and private backups can contain sensitive career material; they are not example files or public portfolio data.
